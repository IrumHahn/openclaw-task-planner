# Task Planner — 과업 설계

이 스킬은 **"무엇을 · 누가"** 를 정하는 제안 단계다. 일을 하지 않고, 에이전트를 만들지 않는다.
실행 규율은 `agent-orchestration`, 정식 채용은 `agent-team-onboarding`이 맡는다. 이 셋의 관계:

```
사용자: "홈페이지 만들고 싶어"
   │
   ▼
task-planner ─ 제안서 1장 ─▶ 사용자 결정
   │                            ├ 규모 소 → 총괄이 그냥 진행
   │                            ├ 규모 중 → agent-orchestration (Lite 원장, 임시 서브에이전트)
   │                            └ 정식 신설 → agent-team-onboarding (승인 후 채용) → 다시 중 경로
```

사용자에게는 사용자의 언어(한국어 수강생이면 한국어)로, 쉬운 말로 말한다.

## 0. 먼저 알아둘 것 (에이전트용)

- 이 폴더의 `references/`만 있으면 동작한다. 스크립트 실행이 필요 없다.
- **만들지 않은 것을 만들었다고, 시작하지 않은 일을 시작했다고 말하지 않는다.**
- 임시 인력은 **서브에이전트 세션**(`sessions_spawn` 등 현재 환경에서 확인된 위임 도구)이다. `openclaw agents add`로 정식 에이전트를 만들지 않는다. 정식 신설은 권고만 하고, 생성은 `agent-team-onboarding`이 사용자 승인 뒤에 한다.
- 제안서에 비밀번호·토큰·개인정보를 넣지 않는다.

## 1. 재료 읽기

워크스페이스에서 **있는 것만** 읽는다. 없으면 "없음"으로 적고 추측하지 않는다.

| 재료 | 위치 | 쓰임 |
|---|---|---|
| 업무지도 | `my-work-map.md` | 과업의 빈도·소요시간·위임 희망도 → 반복 여부 판단 |
| 팀 명단 | `team.md` 또는 `TEAM.md` | 기존 직원의 역할·임무 → "기존으로 되나" 판단 |
| 실제 에이전트 | `openclaw agents list --json` | 명단과 실제 등록이 같은지 |
| 설치된 스킬 | `skills/` 폴더 | 넘길 다음 스킬이 실제로 있는지 |
| 진행 중 원장 | `runs/` | 같은 과업이 이미 돌고 있는지(중복 방지) |

**완료 기준:** 재료 5개의 유무를 안다. 같은 과업의 원장이 이미 있으면 새로 제안하지 않고 그 원장을 가리킨다.

## 2. 과업을 액션플랜으로 쪼개기

과업 1개 → 액션플랜 **3~6개**. 각 액션플랜은 산출물 1개로 끝난다("조사한다" ✗ → "소재 카드 10장" ✓).
큰 목표(예: "유튜브 10만")가 오면 **이번 기간에 할 단위**(예: "10월 영상 4편 기획")로 먼저 좁히고, 그 단위를 쪼갠다. 기간을 모르면 1회만 묻는다.

**완료 기준:** 액션플랜마다 산출물·완료를 눈으로 확인할 문장이 1개씩 있다.

## 3. 규모 판정

[`references/decision-rules.md`](references/decision-rules.md)의 표로 **소 / 중 / 대** 중 하나를 고르고 근거 한 줄을 적는다.

- **소**: 역할 1개 · 산출물 1개 · 외부 부작용 없음 → 제안서는 한 줄. "그냥 진행할게요." 이 스킬 종료.
- **중**: 역할 2개 이상 **또는** 산출물이 서로 의존 → 임시 서브에이전트 + `agent-orchestration` Lite.
- **대**: 중 + **반복 과업**(업무지도 빈도 주 1회 이상)인데 기존 역할로 안 덮임 → 정식 신설 권고.

**완료 기준:** 규모와 근거가 한 줄로 적혀 있다.

## 4. 인력 제안 (3칸)

액션플랜마다 담당을 세 칸 중 하나에 넣는다.

| 칸 | 조건 | 뒤처리 |
|---|---|---|
| **기존으로 됨** | `team.md`의 임무 문장과 액션플랜이 맞음 | 없음 |
| **임시(서브에이전트)** | 이번 과업에만 필요, 반복 아님 | 과업 끝나면 사라짐. 정리 불필요 |
| **정식 신설 권고** | 반복 과업이고 기존 임무 밖 | `agent-team-onboarding`으로 넘김. 지금 만들지 않음 |

검수자는 담당과 **다른** 직원으로 둔다. 둘이 같을 수밖에 없으면 "독립 검수 아님"이라고 적는다.
총괄은 조립·최종 점검을 맡는다.

**완료 기준:** 액션플랜마다 담당 1명 + 검수자 1명, 세 칸 중 어디인지 표시.

## 5. 제안서 보여주고 멈추기

[`references/proposal-template.md`](references/proposal-template.md)대로 **1장**을 보여주고 사용자 결정을 기다린다. 결정 전에는 아무것도 시작하지 않는다.

사용자가 고르면:
- **"그냥 해"** → 총괄이 직접 진행. 제안서는 `runs/`에 저장하지 않아도 된다.
- **"팀으로 해"** → `agent-orchestration` Lite 절차로 넘어가며, 제안서의 액션플랜·담당·검수자를 그대로 원장 작업표의 초안으로 쓴다.
- **"정식으로 뽑자"** → `agent-team-onboarding`을 부른다. 채용이 끝나면 이 제안서로 돌아와 "팀으로 해" 경로를 탄다.
- **"보류"** → 제안서를 `runs/<날짜>-<과업>-proposal.md`로 저장하고 종료.

**완료 기준:** 사용자가 규모·담당·다음 스킬을 알고 결정했다. 결정이 없으면 아무것도 돌지 않는다.

## 지켜야 할 경계

- 제안은 제안이다. 사용자 결정 없이 에이전트 생성·위임·외부 발송·예약을 하지 않는다.
- 업무지도에 없는 반복성을 지어내지 않는다. 반복 여부가 불명확하면 "임시"로 둔다.
- `agent-orchestration`·`agent-team-onboarding`이 설치돼 있지 않으면 그 사실을 말하고, 그 스킬이 할 일을 대신하지 않는다.
- 예제: [`examples/homepage.md`](examples/homepage.md)(규모 중), [`examples/youtube-october.md`](examples/youtube-october.md)(규모 대, 정식 신설 권고 포함).
