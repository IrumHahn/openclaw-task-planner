# 판정 규칙

## 1. 규모

세 질문에 답한 뒤 표에서 고른다. 애매하면 **작은 쪽**으로 둔다 — 커지면 그때 올리면 된다.

| 질문 | 예 | 아니오 |
|---|---|---|
| Q1. 서로 다른 역할(조사·글·디자인·개발·검수…)이 2개 이상 필요한가 | +1 | 0 |
| Q2. 산출물이 서로 의존하는가(A가 끝나야 B를 시작) | +1 | 0 |
| Q3. 업무지도에서 **주 1회 이상 반복**되는 과업인가(또는 사용자가 "앞으로 계속"이라고 했나) | +1 | 0 |

| 합계 | 규모 | 다음 |
|---|---|---|
| 0 | **소** | 총괄이 그냥 진행. 제안서 한 줄 |
| 1~2 (Q3 = 0) | **중** | 임시 서브에이전트 + `agent-orchestration` Lite |
| Q3 = 1 이고, 그 역할을 기존 직원이 못 맡음 | **대** | 정식 신설 권고 → `agent-team-onboarding` |
| Q3 = 1 이지만 기존 직원이 맡을 수 있음 | **중** | 기존 직원으로 Lite 진행 |

외부 부작용(발행·발송·결제·삭제)이 하나라도 있으면 규모와 무관하게 제안서에 **"사용자 승인 필요"** 줄을 넣는다.

## 2. 담당 세 칸

| 칸 | 넣는 조건 | 넣지 않는 조건 |
|---|---|---|
| 기존으로 됨 | `team.md` 임무 문장에 그 일이 들어가거나, 같은 전문성(조사↔리서치, 초안↔글) | 이름만 비슷하고 전문성이 다름(콘텐츠 리서처에게 코딩) |
| 임시(서브에이전트) | 이 과업에만 필요하고 반복 아님 | 업무지도에서 반복으로 잡혀 있음 |
| 정식 신설 권고 | 반복 + 기존 임무 밖 + 사용자 위임 희망도 4 이상 | 위임 희망도 낮음(사용자가 직접 하고 싶어 함) |

정식 신설 권고는 **최대 2명**까지만. 더 필요하면 "먼저 1~2명으로 시작하고 다음 과업에서 재평가"라고 쓴다.

## 3. 검수자

- 담당 ≠ 검수자. 총괄이 기본 검수자.
- 총괄이 담당인 액션플랜은 다른 직원이 검수. 직원이 총괄 1명뿐이면 "독립 검수 아님 — 사용자가 직접 확인"이라고 적는다.

## 4. 중복 방지

`runs/`에 같은 과업 이름의 원장이 있고 상태가 끝나지 않았으면 새 제안서를 만들지 않는다. "이미 `runs/…` 에서 진행 중입니다. 이어서 할까요?"라고 묻는다.
